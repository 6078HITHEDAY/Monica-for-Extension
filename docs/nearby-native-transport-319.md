# Nearby device transport boundary — Android 1.0.319 alignment

This block adds an actual encrypted transport and causal-replica boundary to the extension's Native Host. It does **not** enable nearby sync in the extension UI, import records into the application vault, or establish Android application acceptance. Extension version stays 0.1.37; Host version stays 0.1.2 during development. No release, tag or push is made.

## Source and compatibility

`native/mdbx2-host/vendor/monica-lan-sync` contains unchanged source from Android commit `15b5ec7203c1ba51e19e298aebf2daca82fa55c2`, directory `Monica for Android/rust-lan-sync`. That directory was clean at capture. `LAN-PROVENANCE.json` records normalized SHA-256 for all source files, Cargo manifests/lockfile and the repository license. The crate declares MIT; the original repository license text is also preserved, without relabeling either. The normal supply-chain verifier checks the pinned inventory; future Host packaging includes its provenance and license.

The browser-to-Host feature version is 1. The on-network protocol is Android's v2 Noise protocol with vault content version 2 and `monica-passwords-v1`, including long-term trust, version-vector replica merges, conflicting records, full-vault content and direction negotiation. It does not share a master password. Portability and application shape validation remain separate obligations.

## Implemented boundary

- The browser cannot pass paths or native numeric handles. UUID capabilities are scoped to one Host instance. The Host creates encrypted replicas and snapshot/receive directories under its private root. Per-replica OS leases reject concurrent opens across processes; a wrong key cannot reopen a replica.
- Scans stage complete source scopes before committing. A failed batch poisons that scan: export, mutation and scan completion cannot silently treat missing rows as deletions. Restarting a scan discards the failed staging data. Merge cannot overwrite an active scan.
- Native Messaging keeps the existing 1 MiB input and 900 KiB output frame limits. Larger operations/results use bounded 256 KiB chunks, exact offsets and SHA-256. At most four incoming 8 MiB requests and four outgoing 16 MiB results are staged. Expired buffers are rejected and cleared on the next request; closing the port clears the process. Owned byte buffers are wiped on release.
- Export always requests Android's positive-counter exclusion, including equivalent cached credentials. It never resets a counter, changes a credential/private key, or deletes an omitted source record. Nonexportable-key warnings and per-recipient consent are not implemented by this low-level transport.
- Attachments use the existing Android 512 KiB authenticated chunks. Outgoing chunks must be ordered, fit 64 MiB per file, match a declared asset ID and finish with its complete SHA-256; all declared assets must finish before starting. A partial failed write poisons the snapshot. Snapshots become immutable before transport and remain alive while a worker uses them.
- Received chunks are authenticated by the Rust core. The browser adapter also checks unique asset IDs, order, sizes, final markers and the complete file hash before returning file bytes. No partial file is returned after a validation error.
- Acknowledging receipt as successful requires a replica merge and no pending application writes when data was received. Calling the application-applied operation is still the caller's responsibility after durable vault adoption; this boundary alone cannot prove that an external store was saved.
- Progress exposes fixed diagnostic codes and peer metadata. Host paths, content-encryption keys and vault credentials do not leave the Host. Long-term pairing secrets become available only after authenticated transport; future integration must persist them in the encrypted application vault.
- Native discovery returns a polling handle immediately. Start/connect/progress/cancel use background transport workers. The TypeScript adapter requires a dedicated Native Messaging connection, checks the capability version and closes that connection on cancellation or uncertain failures. It does not silently retry mutations. Production autofill continues using its independent connection.
- Closing the transport cancels all owned transfers immediately and retires their scratch storage only after native release succeeds. A later Host startup scavenges only unleased, owned scratch directories. Encrypted replica journals are retained for explicit reopening.

## Validation

Evidence is local under `.artifacts/nearby-*20261012*`; it contains only synthetic vaults and isolated profiles. New tests cover the boundary and byte preservation, not real Android UI or provider adoption.

- Nine native boundary tests passed, including real TCP/Noise duplex transfer, trust reconnect, direction changes, positive-counter exclusion, merge/apply acknowledgement gates, encrypted reopen, cross-process leases, poisoned scans, path rejection, asset integrity, cancellation cleanup and asynchronous discovery.
- All 80 Host tests passed, including existing MDBX object/attachment/recovery/Windows Hello regressions.
- All 36 tests in the pinned Android LAN core passed under the Host dependency graph, including wrong pairing secrets, unexpected peer identity, large duplex artifacts, both-party merge confirmation and cancellation.
- Seventeen TypeScript tests passed for large request/result framing, exact data, corrupted buffers, offset mismatch, cancellation, lost replies, unsafe integer rejection, attachment integrity and empty files.
- Full extension run covered 3,490 tests in 289 files: 3,444 passed initially and 46 hit the existing 5-second timeout while the full native suite and build were also running. All 211 tests in those seven affected files passed when rerun at one worker without competing builds. The original failures are retained; no timeout or assertion was relaxed and no product fix was needed for that rerun. Future consolidated suites should run the expensive native and JavaScript tests sequentially.
- Installed Edge **155.0.4283.45**, two isolated profiles with actual Native Messaging: **16.4 s**, passed. A browser-generated P-256 key, a 770,240-byte project and a 600,000-byte attachment crossed the real Rust transport. The receiver was closed after encrypted merge and before adoption; after full browser/native restart, reopening its encrypted replica recovered exactly the same pending records. A trusted send-only/receive-only reconnect recovered the attachment and finished without duplicate records. The received PKCS8 key signed a fresh challenge against the original SPKI public key. Original IDs/private bytes, zero counter and the source positive counter 19 were unchanged. Native registration was restored.
- The Edge fixture uses a minimal test extension bundling the production adapter and Native Messaging client. It is not the manager UI and does not count simulated application-applied calls as durable application-vault adoption. Neither Android sources nor an Android build/device nor user browser profiles/accounts were used.
- Production build and project/interop types passed. The 218-command security audit passed. Existing bundle-size warnings remain.
- Strict E2E/new-test types, Clippy with warnings denied, source-provenance verification and whitespace checks passed. Packaging scripts include/check LAN provenance and source licensing; a new release archive was not built or published in this block.

## Remaining integration

Map current Android password/project, Passkey, OTP/Steam, note/card/address, folder/label/relation, recycle-bin and attachment shapes to/from the application and MDBX stores. Preserve unknown fields and associations, validate key material/public identity, re-protect incoming private material and durably adopt files/records before replica acknowledgement. External Bitwarden/KeePass accounts must retain Android's separate-sync policy. The current TypeScript boundary rejects unsafe integers rather than rounding causal clocks; future lossless application mapping must decide how to retain wider numeric lexemes.

Add encrypted device identity/trust/preferences; peer presence, foreground/unlocked/edit lifecycle, automatic and manual rounds; exact per-recipient restricted-Passkey confirmation; local M3E Canvas and actual settings UI. Bind scan scope changes and replica handles to the selected source/session. Implement application recovery across lost replies and mixed provider failures, including lost receiver files after a crash. Finally, verify actual current Android/F-Droid applications and devices on a real network. These remain open and must not be described as completed by the transport tests.
