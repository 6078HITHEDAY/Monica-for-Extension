# Native Wi-Fi hierarchy scheduling — Android 1.0.320 alignment

This extension-only checkpoint follows Android's existing folder paths, tombstones and password fields. It completes bounded coordinator scheduling after the [retained-folder checkpoint](nearby-folder-trash-320.md). It does not change Android, the native engine, Passkey material or counter policies. Full Wi-Fi and Android parity remain unfinished.

## Behavior

The coordinator orders whole password/reference components by folder dependencies before selecting at most 128 records. Incoming parent creation/restoration precedes descendants. A deleted parent waits for children and items to be deleted or moved out, using their current bound paths even when new paths no longer mention that parent. Authenticated aliases are resolved before ordering. Dependency cycles reject the plan before selecting a prefix; adaptive native limit retries keep both prerequisites and complete password projects. Folder membership does not combine an entire directory into an unbounded transaction.

Sparse native passwords previously gained `login_type`, `is_archived`, `archived_at` or `kind` extension fields during reconstruction. The next scan could interpret those defaults as local edits, producing conflict copies during deletion. A local `device_sync_password_projection` marker records only reconstruction differences and restores original presence/values while the corresponding native value is unchanged. Intentional later edits take precedence. The marker is stripped from outgoing wire data and validated for version, field count, unique bounded keys and consistent presence/value pairs. Arbitrary JSON keys are restored as own properties. Local editor projection uses the same rule, preventing false writes on local → native → local round trips. Android fields are not globally removed or redefined.

Pure trash/restore transitions emit only the native deletion-state command when the exact projected content is otherwise equal. Payloads, file identities and metadata are retained; exact numeric JSON is distinguished from literal objects. Incoming planning reuses the latest complete scan only for the same provider, handle and source hash after rereading the native revision. Writes clear the cache and retain existing native authorization, revision guards and encrypted intent/receipt recovery. Outgoing capture always rereads the native source and policy.
