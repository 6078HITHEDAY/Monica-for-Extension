# Bitwarden 项目移除：本地使用和编辑恢复

2026-10-10，扩展 0.1.37。当前 `dist` 已更新，未提交或发布。本批继续完整 Android 对齐目标，不代表整体互通验收完成。

## 修复

之前的移除日志把 Passkey 最近使用时间、使用次数也纳入唯一的快照摘要。复制或删除期间登录一次就可能导致后续恢复一直拒绝；真正的本地编辑也无法转入已存在的冲突处理界面。

- 新冻结的凭据记录同时保存完整摘要和排除两项本机使用统计的摘要。凭据 ID、私钥、签名计数及其历史高水位、备份/验证策略、其他内容和来源引用仍受严格校验。旧日志不自动改写；没有新摘要时继续使用完整摘要。
- Passkey 使用统计在保留副本、删除和最终采用期间都可更新，最终保持原本地 ID 和最新使用记录，不产生额外上传、删除或恢复。
- 删除意图冻结之后，如果登录项、Passkey 或验证器内容被本地编辑，则停止继续删除，持久化恢复进度并恢复本次已经触及的远端原项。未发送删除的原项保持不动，不把旧密码快照写回服务器。
- 恢复结果、本地编辑、两份冲突版本、队列清理及取消状态一起加密保存。普通同步不再被这条移除日志卡住；冲突必须通过原有“保留浏览器版本／采用 Bitwarden 版本”明确选择。
- 恢复期间的来源绑定、原项身份与未知请求回执仍有检查。来源改绑、原记录身份消失、尚未确认的写入回执不能通过这条路径被静默清除。
- 原有 Bitwarden 冲突界面增加新说明的离线翻译。未新增运行时命令；Android、凭据密钥/ID 和零计数设计未修改。

## 验证

13 个相关测试文件、325 项回归通过，41.74s，记录 `.artifacts/bw-removal-local-recovery-regression.log`。覆盖三种记录在删除前、删除响应后和远端已提交后的本地编辑；最终冲突保存失败、加密重启恢复；本地版本选择；复制前、删除中及提交后的 Passkey 使用记录；计数、密钥、备份标志等不可忽略字段。类型检查发现新测试夹具缺少三个必填属性，补全后 14 项摘要检查复验通过，生产构建通过。

真实 Edge / MV3 / IndexedDB 共 7 条不同流程通过：原有完成、响应丢失后继续、取消、编辑器确认和来源设置路由，以及新增两种冲突选择。初次新增远端选择用例漏写确认标题中的空格，6/7 通过；修正定位后两种选择均复验通过，24.9s。

两条新增流程都通过实际后台命令在远端删除响应期间注入本地密码编辑，经管理页确认选择后执行两次普通同步，独立解码远端 Cipher 验证选中的密码。两枚原始 Passkey 和两份独立副本均能使用私钥签名，并以原始公钥验签；计数保持 0 / 23，原本地 ID 保持。每条流程只有 2 次复制、1 次删除和 1 次恢复，敏感内容不显示在冲突或确认界面。

HTTP 由 Playwright 合成路由提供；这些结果不是实际 Bitwarden/Vaultwarden、Android Credential Manager 或 GitHub RP 验收。已有用户确认的 GitHub 登录与响应正常不被扩大为全部跨端通过。
