# Native collection profile inventory — Android 1.0.320 alignment

The extension now reads complete native collection profiles before building a nearby source inventory. This is the read/disclosure boundary needed for subsequent portable archives and profile restoration, not completed profile adoption. Android production sources and its wire protocol are unchanged.

## Source contract and data safety

Current Android `DeviceNativeFolderMetadata.read` preserves saved folder payload extras, paths and tags but does not apply native collection profiles. A profile cannot therefore be assumed to work merely because its folder name transferred. The browser's previous completeness check missed profiles with schema version 1 and default presentation fields, allowing an apparently complete scan to omit their payload/type/capability declarations. A focused red regression reproduced this; all declared profiles now require the unfinished archive/restore path before a sync scan is allowed. Favorite/archive/icon checks remain in place.

`content.metadata.read` adds the `collection-profile` kind, advertised by `supportsContentProfiles`. Each chunk requires an open vault, checks the expected write revision, authorizes `RevealSecret` on the owning project with conservative Standard browser posture, checks the revision again, reads the profile and matching collection summary, then checks the revision before returning. Denied, stale or unavailable content returns an error without profile bytes. The raw FFI getter is never called before authorization. Required capabilities are returned as data; they are not registered or enabled. Existing label/relation disclosure retains its policy boundaries.

Payloads remain binary; no UTF-8 or JSON conversion occurs. The response carries original type/schema, allowed object types, required capabilities, timestamps/device identities, matching collection head/deletion state and SHA-256. Payloads are capped at 1 MiB, chunks at 256 KiB and responses at 850 KiB. The native buffer is zeroized after each response. The TypeScript collector snapshots caller input, validates every response and metadata identity, checks canonical Base64, offsets, size, complete content hash and final revision, and wipes temporary byte buffers. Cancellation or any invalid chunk rejects the whole result. At most 10,000 profiles and 32 MiB of aggregate profile data/metadata can be collected.

Nearby inventory checks the returned profile set against all profile-bearing collections with a map, avoiding quadratic directory scans. Profile data is kept separate from the lossy editor projection. Collections without profiles need no additional capability request; older engines fail explicitly when complete profile disclosure is required.

## Verification

- 152 TypeScript cases in five files cover binary/empty profiles, chunk identity/integrity/metadata changes, malformed responses, duplicate declarations/owners, limits, cancellation, native denial, caller mutation, stale source revisions, missing profiles and the schema-1 omission regression, plus existing client/metadata behavior.
- Two native profile tests passed in 40.54 seconds initially and 57.94 seconds after ensuring the plaintext buffer is zeroized on summary-validation failures: 300,000 arbitrary bytes and declarations, unchanged revision on read, lock/reopen, stale revision rejection and Power-mode denial before disclosure. Six existing native metadata tests passed in 55.34 seconds, including label/relation reconstruction, bounds, stale/locked reads and Power denial. Final all-target Clippy passed. This was the affected eight-test native set, not a rerun of all 104 native tests.
- Rebuilt Native Host debug executable and bundled browser engine with Rust 1.97.0/Emscripten 4.0.18. Final WASM is 6,447,372 bytes, SHA-256 `0a1c6ee5326bcd20d5b113e1d4e2e7ffe45d561288752f30b29a825f750a6abc`. No vendored engine change or new source overlay was necessary; the existing seven overlays are unchanged.
- Actual isolated Edge test passed in 10.8 seconds initially and 23.1 seconds with the final engine (25.7-second runner). A native test creates an encrypted MDBX fixture with 300,000 arbitrary bytes. The browser imports it through the real transfer API, reads the complete source with the rebuilt engine, verifies every byte and declaration, checks encrypted IndexedDB storage, confirms locked reads fail, restarts the browser and compares the complete profile and revision. The schema-1 scan correctly reports its still-missing archive/restore path. This test does not claim Android application adoption.
- Existing real native catalog regression passed in 4.5 seconds and production coordinator regression in 1.5 minutes (combined runner 1.6 minutes). They preserve folder metadata, original Passkey keys and zero counter, 142 records including a whole 40-record password group, attachment bytes, reciprocal edits, trash/restore and repeat-sync no-op. These are functional acceptance timings on a shared desktop, not a throughput improvement claim. The final native buffer-cleanup change affects only profile reads, revalidated by the final profile test.
- Main/interop and strict affected E2E types, production build, source/artifact provenance and the security audit passed. Audit covers 219 runtime commands, 24 password-project commands and the dedicated nearby manager port.

Evidence is under `.artifacts/nearby-profiles-*`: `v1-red.log`, `unit-first.log`, `unit-final-2.log`, `native-final-2.log`, `native-metadata.log`, `native-clippy-final.log`, `host-build-final.log`, `browser-build-final.log`, `edge-final.log`, `final-regression.log`, `production-final.log`, `security-final-3.log` and `e2e-types-final-2.log`. The first native test run used a nonexistent `vault.close` test command; it failed visibly and was corrected to the actual `vault.lock` API before the final pass. No assertions or security constraints were relaxed.

The broader Wi-Fi goal remains active: complete portable profile archives and native restoration, unsupported object/schema archives, Android/F-Droid attachment bytes/UI/multicast and wider backend/OneDrive acceptance. Local `dist` is updated; public 0.1.39 Preview is unchanged. No Android edit, emulator operation, outgoing main-chat message, push, tag or Release occurred. Synthetic Edge profiles are automatically removed; existing Canvas files and evidence are preserved.
