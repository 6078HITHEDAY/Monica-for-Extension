# Bitwarden Steam 附件不可用修复 — 2026-10-10

用户截图中的两个 Steam 条目均来自 Bitwarden：条目可见，但验证码不可用，详情缺少 SteamID 与会话数据。使用合成账号经真实 Provider、加密 Cipher、附件下载和解密复现了同类失败，没有访问用户 Chrome 密码库或读取用户密钥。

## 原因与修复

Android 当前 `BitwardenAttachmentCrypto.kt` 使用标准二进制格式 `2 || IV(16) || HMAC(32) || AES-CBC ciphertext`；插件仍仅接收历史 `IV || ciphertext || HMAC`，导致标准附件完整性校验失败。新读取器按总长度区分两种布局，不能按首字节判断，因为旧 IV 也可能以 2 开头。两种格式均验证 IV 和全部密文的 HMAC 后才解密、产生可读取会话；不接受不带 MAC 的降级格式。

附件密文按固定大小块有界保留，转换时逐块清理，失败或取消也清理缓冲。Steam 专用下载实例限制明文 1 MiB；声明缺少大小时仍有网络及解密大小限制。新上传使用标准格式，并以独立 WebCrypto 解密和 MAC 验证检查实际上传字节；历史上传恢复按已准备的密文大小保留原布局和附件身份，不重复创建。

另两个回归点：同步缓存发现远端版本未变时提前返回，导致前次失败的 Steam 附件不再重试；maFile 读取使用普通 JSON 且仅识别字符串 SteamID，并把普通网页 URL 当作验证码密钥。现已允许未完成 Steam 数据继续读取，成功后仍走快速缓存；数字 SteamID 无损读取，普通网页 URL 不干扰 `shared_secret`，保留原 maFile 文本。

未更改 Steam 的会话权限规则。验证码只依赖 `shared_secret`；交易确认、库存等联网操作仍需有效会话信息。Passkey ID、私钥和零计数策略没有变化。

## 验证

- 修改前：真实 Provider 合成测试 5 项中 4 项失败，分别覆盖标准格式、数字 ID/普通 URL、无版本变化的失败重试、未知附件大小；旧格式基线通过。两种上传模式的独立标准格式断言均失败。
- 修改后：针对性读取、解析、上传及恢复测试 56 项通过；Bitwarden 和附件完整测试 33 个文件、418 项通过。随后新增两种模式的历史上传恢复用例，所在文件共 17 项通过（累计 420 项不同用例）。
- 最终构建完成后，真实 Edge 3 项场景全部通过（20.4 秒）：Bitwarden 登录→同步标准加密附件→先失败显示不可用→重试恢复验证码和精确 SteamID；本地及 URI Steam 验证码；实际加密 KDBX maFile 及文件夹筛选。验证码均与独立 Node HMAC 结果核对。缺少会话 token 时显示网络操作错误，验证码保持可用。实际截图已检查，仅保留本地。
- 标准格式的分块边界、旧 IV 首字节为 2、篡改 IV/MAC/密文、未知类型、大小限制、取消和跨域请求不携带账号 bearer token 均有覆盖。
- 生产构建、TypeScript、图标/扩展页面检查、E2E 类型检查和 212 条命令安全审计通过。
