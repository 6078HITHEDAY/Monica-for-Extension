# Wi-Fi sync integration and receipt recovery

The manager now exposes Wi-Fi synchronization for a selected local or bundled/native MDBX source. Pairing establishes trust without sending vault contents. Saved peers can be discovered through local IPv4 hints, with device and pair identities checked before the authenticated transport connects. Automatic synchronization runs only while this unlocked manager page owns the session. Passkey compatibility review still requires an explicit decision.

Native adoption uses the existing backend router and provider operation lock. Before writing, the encrypted vault stores the original operation, revision, complete plan, assets and acknowledgement baseline. An uncertain result retains this intent. Recovery repeats that same operation and accepts the original durable receipt; subsequent source scans refresh actual guards without treating later edits as the received baseline. Only a definite stale rejection discards an unapplied intent. Source changes require removing pairings and resolving pending adoption first.

Real browser integration exposed two defects: an offscreen MDBX document disconnected unrelated runtime ports, and historical domain UUIDs were incorrectly validated as runtime session handles. Unrelated ports are now ignored; domain identities preserve all 128 bits while session/operation handles retain their stricter validation.

Validation on 2026-10-14: 242 affected unit cases passed. Installed Edge 155 passed production local ↔ bundled MDBX synchronization, repeated synchronization without native writes, the real settings pairing/discovery/cancellation path, and the existing settings accessibility/navigation checks. A real browser close/reopen after native commit but before acknowledgement recovered the encrypted intent through the production adapter, preserving subsequent edits, the original Passkey signature and counter 19. Durable journal/native-block scans found no synthetic plaintext. Zero-counter preservation passed separately. The UI generation guard prevents a cancelled operation from changing a later connection's state.

This is an integration checkpoint, not final Android interoperability acceptance. Retained deleted native payload access, unsupported native content/archives, folder assets/profiles, and actual Android/F-Droid bidirectional application acceptance remain open. LAN transport needs the local communication helper; MDBX storage itself is bundled. Public release 0.1.39 is unchanged.
