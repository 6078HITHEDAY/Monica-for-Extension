# 0.1.47 preview-beta 发布验证

## 中文

2026-10-20，按用户要求发布 0.1.47 preview-beta：GitHub 正式 Release，未标记 Pre-release，标签 `v0.1.47`。本版只修复 Edge 侧栏 Wi-Fi 同步连接被后台误判的问题，并补充 Android 必须选择“双向同步”的说明。

- **版本与身份**：`package.json`、`package-lock.json` 与 `public/manifest.json` 均为 `0.1.47`。从 `dist/manifest.json` 读取的公钥与 `public/manifest.json` 逐字节一致；按 Chrome 扩展 ID 规则计算得到 `lebnfedmijifofonogjdphpojihgohmc`。manifest 继续声明 `minimum_chrome_version` 128，`dist` 六个公开语言目录均包含新增的 `manager-context-invalid` 文案。
- **构建**：`npm run build` 通过，转换 435 个模块；4 个扩展页面通过本地资源引用检查；MDBX2 Host 固定提交 `90005c8c608c952093a4522ffa507a562e2e39a4`、8 个显式扩展覆写与 180 个 vendored 文件校验通过；内置 Windows Wi-Fi 安装组件能力握手通过，SHA-256 为 `15d8a52a9bcd2d40338825023b3ca85101ff19105f7eb6e93a0e4ccf739827b5`。
- **单元测试**：全量 `npm test` 共 321 个文件、4,113 项，4,106 项通过。7 项在并发负载下达到既有 5 秒超时，分布在 `bitwarden-batch-coordinator.test.ts`、`bitwarden-keepass-move.test.ts` 与 `bitwarden-project-batch.test.ts`；这三个文件单独重跑共 66／66 通过（11.97 秒）。首次全量运行另有多项失败，原因是新增的 `manager-context-invalid` 文案只加入了 `src/i18n/ui-en.json`，六个公开语言目录尚未同步；补齐后 `src/i18n/runtime.test.ts` 28／28 通过，再进行上述全量复跑。本记录不宣称重跑过第二轮全量测试。该超时现象与 0.1.46、0.1.39 记录过的并发超时一致。
- **安全审计**：`node scripts/security-audit.mjs` 通过，检查 218 个运行时命令（含 24 个仅管理页可用的密码项目命令），并核对独立附近同步管理端口的文档归属、请求上限、脱敏与生命周期取消。
- **Edge 侧栏实测**：在真实 Edge `155.0.4283.62` 中，修复前侧栏显示“同步连接已关闭，请重新连接。”；提交 `1d91adc` 修复后同一侧栏成功建立 `nearby-manager` 端口，页面改报 `peer-not-found`（未在当前网络中找到已配对的手机），证明精简 sender 的文档校验已通过。Chrome `155.0.8059.85` 已安装但未针对本修复单独执行真实验证。
- **打包**：发布包从干净的版本提交 `ebb2e6e880bbf5f58406c940dc7d9d8e4609b842` 生成。`npm run package:release` 生成 1,142 个文件的 ZIP（SHA-256 `bd429ca070b05f026f1100a6bf86f79cee04e65da0dbcfb5bfc0d70dc3bad08f`，13,658,541 字节），`npm run package:verify` 校验哈希、清单、内容，并确认两次独立封包逐字节一致。源码提交、锁文件与内容哈希以随包的 `SECURITY-EVIDENCE.json`、`RELEASE-METADATA.json` 和 `.zip.sha256` 为准。发布页只上传 ZIP 与校验文件。

**未运行／未验收**：没有运行完整 `release:check`（包含联网 npm 审计、Rust 测试和 Playwright E2E），没有在真实 Chrome 中执行 OneDrive 登录。Wi-Fi 同步的真实手机验收仍未完成：本机 WLAN 为 `192.168.43.225/24`，对 `192.168.43.1–254` 的 53318 端口与组播 `224.0.0.168` 探测均无响应，说明探测时手机未处于“立即同步”监听状态；`peer-not-found` 属于环境问题，不是连接被断开。Firefox 不支持，Edge 仅验证侧栏连接路径，其余界面与流程未做本版全量验收。OneDrive 的 Entra SPA 回调虽已登记，真实登录、令牌刷新与 Graph 读写仍未验证；外部账号可能受发布者验证或管理员同意限制。不宣称通过稳定版全量门禁。

## English

User-authorized 0.1.47 preview-beta, reviewed on 2026-10-20: a regular GitHub Release, not marked Pre-release, tag `v0.1.47`. This build only fixes the background rejecting the Edge side-panel Wi-Fi connection and documents that Android must use bidirectional sync.

- **Version and identity**: `package.json`, `package-lock.json` and `public/manifest.json` are all `0.1.47`. The public key read from `dist/manifest.json` is byte-identical to `public/manifest.json`; Chrome's extension-ID derivation yields `lebnfedmijifofonogjdphpojihgohmc`. The manifest still requires Chrome 128+, and all six public locale catalogs in `dist` contain the new `manager-context-invalid` message.
- **Build**: `npm run build` passed with 435 transformed modules; all four extension pages passed local-asset checks; the MDBX2 Host pin `90005c8c608c952093a4522ffa507a562e2e39a4`, 8 explicit extension overlays and 180 vendored files verified; the bundled Windows Wi-Fi helper capability handshake passed with SHA-256 `15d8a52a9bcd2d40338825023b3ca85101ff19105f7eb6e93a0e4ccf739827b5`.
- **Unit tests**: the full `npm test` run covered 321 files and 4,113 tests; 4,106 passed. Seven tests hit the existing five-second timeout under concurrent load in `bitwarden-batch-coordinator.test.ts`, `bitwarden-keepass-move.test.ts` and `bitwarden-project-batch.test.ts`; all three files passed 66/66 when rerun in isolation (11.97 s). The first full run had additional failures because the new `manager-context-invalid` message had only been added to `src/i18n/ui-en.json`, not the six public locale catalogs; after completing them `src/i18n/runtime.test.ts` passed 28/28 and the full suite was rerun. No second full run is claimed. The timeout behaviour matches the concurrency timeouts recorded for 0.1.46 and 0.1.39.
- **Security audit**: `node scripts/security-audit.mjs` passed, covering 218 runtime commands (including 24 manager-only password-project commands) and the dedicated nearby manager port's ownership, request bounds, redaction and lifecycle cancellation.
- **Live Edge check**: on real Edge `155.0.4283.62`, the side panel previously showed “connection closed, reconnect”; after commit `1d91adc` the same panel established the `nearby-manager` port and reported `peer-not-found` (no paired phone found on the network) instead, proving the reduced side-panel sender now passes document validation. Chrome `155.0.8059.85` is installed but was not separately exercised for this fix.
- **Packaging**: artifacts are produced from clean version commit `ebb2e6e880bbf5f58406c940dc7d9d8e4609b842`. `npm run package:release` produced a 1,142-file ZIP (SHA-256 `bd429ca070b05f026f1100a6bf86f79cee04e65da0dbcfb5bfc0d70dc3bad08f`, 13,658,541 bytes); `npm run package:verify` checked the hash, inventory and contents and confirmed two independent packages are byte-identical. The authoritative source commit, lockfile and content hashes are in the embedded `SECURITY-EVIDENCE.json`, `RELEASE-METADATA.json` and `.zip.sha256`. Only the ZIP and checksum are uploaded.

**Not run / not accepted**: the complete `release:check` (online npm audit, Rust tests and Playwright E2E), and real OneDrive sign-in in Chrome. Real-phone Wi-Fi sync acceptance is still outstanding: the host WLAN is `192.168.43.225/24`, and probes of port 53318 across `192.168.43.1–254` plus multicast `224.0.0.168` returned nothing, meaning the phone was not in its “sync now” listening state at probe time; `peer-not-found` is environmental, not a dropped connection. Firefox is unsupported and Edge is accepted only for the side-panel connection path, not its full UI. The Entra SPA redirect is registered, but real sign-in, token refresh and Graph read/write remain unverified; external accounts may still be limited by publisher verification or admin consent. This does not claim the full stable-release gate.
