# 卡面附件读取失败修复（2026-10-21）

用户报告 Android 同步至 Monica 本地库的卡面随机无法读取；刷新后失败项目会变化，详情偶尔成功。

## 复现与原因

列表为每个进入视口的卡片同时调用 `readVerifiedAttachment`，后台的本地附件读取限制为四个活动句柄。前端没有排队，超限后将卡片永久标为失败，直至重新挂载或相关数据变化。12 个同时请求的回归测试在修改前有 8 个超限失败。

真实 Edge 的生产构建测试使用独立配置、12 张合成卡片及 PNG 附件，其中四张省略 MIME 元数据。旧构建最终仅有 3 张图片完成加载，断言失败。初始测试脚本还分别遇到上传完成回执未释放及宽屏导航已展开的测试设置问题；更正脚本后取得上述实际图片加载失败证据，这些脚本问题不计入产品复现。

另一个确定的问题是图片选择器接受无 MIME 的 `.png` 等文件，展示组件却要求精确图片 MIME，导致可选图片无法展示。整个项目对象被替换还会导致原卡面无必要地取消并重新读取。

## 改动

- 所有经过验证的前端附件预览共享两个读取名额，覆盖列表、详情和手动预览。名额保持到后台句柄释放完毕，不缓存解密图片。
- 排队请求可取消；后台明确返回 `attachment-read-limit` 时最多等待 10 秒重试。其他错误、丢失响应、完整性失败或锁库失败不重放读取开始请求。本地后端增加同样的稳定错误码，后台四句柄限制保持不变。
- 卡面只在归属、版本、来源或图片名称变化时重读，不因相同项目对象重新创建而取消。
- 卡面与详情预览按文件头识别 PNG/JPEG/GIF/WebP，支持缺失或通用 MIME。其他格式及 HTML/SVG 不作为卡面嵌入；无法解码的图片仍显示失败，不修改原附件。

原有附件分页、分块身份、大小、摘要校验和锁库/会话检查继续执行。此次没有调整视觉布局。

## 验证范围

针对性单元测试覆盖并发图库、排队取消、仅忙碌拒绝可重试、丢失响应不重试、句柄释放、缺失 MIME 的光栅识别及活动内容拒绝。本地附件与上传/分块相关回归继续通过。

真实 Edge 测试 `tests/e2e/card-artwork.spec.ts` 覆盖 12 张图片全部解码、无 MIME 图片的详情与独立预览、刷新多轮、已占满四个后台名额时等待释放、项目实时更新、锁定清除和重新解锁。卡包新建相关回归也通过。TypeScript、Chromium/Firefox 生产构建和安全静态审计通过；CI 增加这项 Edge 回归。

测试仅使用合成附件和独立 Edge 配置，未打开 Chrome、读取个人浏览器配置或用户图片，也未启动 Android 虚拟机。这次模拟 Android 同步后的本地附件结构，没有重新执行真机同步链路。证据日志保存在 `.tmp/card-artwork-*.log`，截图仅在本地测试结果中。
