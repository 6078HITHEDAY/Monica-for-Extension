# 0.1.48 preview-beta 发布验证

## 中文

2026-10-20，按用户要求发布 0.1.48 preview-beta：GitHub 正式 Release，未标记 Pre-release，标签 `v0.1.48`。本版修复 Wi-Fi 同步的 TOTP 解析（0.1.47 曾把 Android 省略的默认值读成 4 位验证码），并新增解锁时对已导入本地记录的修复。

- **版本与身份**：`package.json` 与 `public/manifest.json` 均为 `0.1.48`。从 `dist/manifest.json` 读取的公钥与 `public/manifest.json` 逐字节一致；按 Chrome 扩展 ID 规则重新计算得到 `lebnfedmijifofonogjdphpojihgohmc`。manifest 继续声明 `minimum_chrome_version` 128。
- **本版代码**：解码修复见提交 `8962f1d`（`androidTotpNumber`：缺失或空值回退 Android 默认 6 位／30 秒；显式值仍按 4–10 收敛），已导入记录修复见提交 `00f0f16`（新增 `src/nearby/local-totp-repair.ts`，在 `migrateVaultState` 解锁迁移时用附近设备同步保留的原始 `item_data` 复核：仅当原始载荷没有 `digits` 字段时把持久化的 4 改回 6；Android 明确保存的位数不动；回收站条目同样修复）。
- **构建**：`npm run build` 通过（含 `tsc -b`、互操作类型检查、图标字体校验、Vite 构建、worker 构建与页面资源校验）；4 个扩展页面通过本地资源引用检查；MDBX2 Host 固定提交 `90005c8c608c952093a4522ffa507a562e2e39a4`、4 个 Android 覆写、8 个显式扩展覆写与 180 个 vendored 文件校验通过；内置 Windows Wi-Fi 安装组件能力握手通过，SHA-256 为 `91a14e43f6ebf7d8b81a23b1c67d213338b78882907096596a50201bf11ee20b`。
- **单元测试**：目标回归先单独运行，`src/nearby/local-totp-repair.test.ts` 6／6、`src/core/migrations.test.ts` 12／12、附近同步与 TOTP 相关目录合计 317／317 通过。全量首次 `npm test`（默认 5 秒超时）为 322 个文件、4,131 项，4,127 项通过；4 项在并发负载下超时，分布于 `bitwarden-keepass-move.test.ts` 与 `bitwarden-project-batch.test.ts`，这两个文件单独重跑 29／29 通过。随后以 `npx vitest run --testTimeout=20000` 重跑全量，322 个文件、4,131 项全部通过（61.96 秒）。超时现象与 0.1.46、0.1.47 记录过的并发超时一致，不属于本版改动引入的失败。
- **安全审计**：`node scripts/security-audit.mjs` 通过，检查 218 个运行时命令（含 24 个仅管理页可用的密码项目命令），并核对独立附近同步管理端口的文档归属、请求上限、脱敏与生命周期取消。
- **打包**：发布包从干净的版本提交 `00f0f16598ead47226b19cfebd44e0d95b9185a7` 生成，包内 `SECURITY-EVIDENCE.json` 记录 `trackedWorktreeClean: true`。先执行 `npm run build`，再由 `node scripts/package-release.mjs` 生成 1,142 个文件的 ZIP（SHA-256 `a7a6d1080bb465675ac7abb8f25a3945c209227ae5a0df5d8f64246cdd7a5077`，13,758,195 字节）；`node scripts/verify-release.mjs` 校验哈希、清单、内容，并确认两次独立封包逐字节一致。发布页只上传 ZIP 与 `.sha256`。

**未运行／未验收**：没有运行完整 `release:check`（包含联网 npm 审计、Rust 测试与 Playwright E2E）。已导入 4 位记录的修复只以合成 fixture 验证了解锁迁移路径，未在真实浏览器中打开旧密码库核对显示，也未在真实手机上复测同步；修复依赖密码库中仍保留的附近同步接收记录，若该记录缺失或不可解析则不会改动条目。已删除到回收站的条目不会被重新导入：删除是同一同步记录上的软删除，Android 端记录未变化时“仅接收”不会产生新的接收项；恢复条目或先在 Android 复制出新记录再同步，才会得到新的本地副本。Firefox 不支持；真实手机首次同步、Android 自动调度与 OneDrive 真实登录仍未验收。不宣称通过稳定版全量门禁。

## English

User-authorized 0.1.48 preview-beta, reviewed on 2026-10-20: a regular GitHub Release, not marked Pre-release, tag `v0.1.48`. This build fixes Wi-Fi-sync TOTP parsing (0.1.47 read Android's omitted defaults as a 4-digit code) and adds an unlock-time repair for records already imported locally.

- **Version and identity**: `package.json` and `public/manifest.json` are both `0.1.48`. The public key read from `dist/manifest.json` is byte-identical to `public/manifest.json`; recomputing Chrome's extension ID yields `lebnfedmijifofonogjdphpojihgohmc`. The manifest still requires Chrome 128+.
- **Code in this release**: the decoder fix is commit `8962f1d` (`androidTotpNumber`: missing or empty values fall back to Android's 6 digits / 30 s; explicit values are still clamped into 4–10). The persisted-record repair is commit `00f0f16` (`src/nearby/local-totp-repair.ts`, invoked from `migrateVaultState` at unlock): it re-reads the original `item_data` retained by the Nearby Sync receipt and restores an omitted digit count from 4 to 6, while leaving any explicitly stored Android digit count untouched, including trashed items.
- **Build**: `npm run build` passed (including `tsc -b`, the interoperability typecheck, icon-font verification, the Vite build, worker builds and page-asset checks); all four extension pages passed local-asset checks; the MDBX2 Host pin `90005c8c608c952093a4522ffa507a562e2e39a4`, 4 Android overlays, 8 explicit extension overlays and 180 vendored files verified; the bundled Windows Wi-Fi helper capability handshake passed with SHA-256 `91a14e43f6ebf7d8b81a23b1c67d213338b78882907096596a50201bf11ee20b`.
- **Unit tests**: targeted regressions ran first — `src/nearby/local-totp-repair.test.ts` 6/6, `src/core/migrations.test.ts` 12/12, and the nearby-sync/TOTP suites totalled 317/317. The first full `npm test` run (default 5 s timeout) covered 322 files and 4,131 tests; 4,127 passed. Four tests timed out under concurrent load in `bitwarden-keepass-move.test.ts` and `bitwarden-project-batch.test.ts`, and those two files passed 29/29 when rerun in isolation. A second full run with `npx vitest run --testTimeout=20000` passed all 322 files and 4,131 tests (61.96 s). The timeout behaviour matches the concurrency timeouts recorded for 0.1.46 and 0.1.47 and is not a failure introduced by this release.
- **Security audit**: `node scripts/security-audit.mjs` passed, covering 218 runtime commands (including 24 manager-only password-project commands) and the dedicated nearby manager port's ownership, request bounds, redaction and lifecycle cancellation.
- **Packaging**: artifacts are produced from clean version commit `00f0f16598ead47226b19cfebd44e0d95b9185a7`; the embedded `SECURITY-EVIDENCE.json` records `trackedWorktreeClean: true`. After `npm run build`, `node scripts/package-release.mjs` produced a 1,142-file ZIP (SHA-256 `a7a6d1080bb465675ac7abb8f25a3945c209227ae5a0df5d8f64246cdd7a5077`, 13,758,195 bytes); `node scripts/verify-release.mjs` checked the hash, inventory and contents and confirmed two independent packages are byte-identical. Only the ZIP and checksum are uploaded.

**Not run / not accepted**: the complete `release:check` (online npm audit, Rust tests and Playwright E2E) was not run. The persisted 4-digit repair is verified only through the unlock-migration path with synthetic fixtures; it was not exercised against an old vault in a real browser, nor re-tested with a real phone. The repair depends on the Nearby Sync receipt still being present and parseable; without it, items are left unchanged. Items already moved to trash are not re-imported: deletion is a soft delete on the same sync record, so receive-only sync produces no new adoption while the Android record is unchanged. Restoring the item, or duplicating it on Android so a new record is created, is what yields a fresh local copy. Firefox is unsupported; real-phone first sync, Android automatic scheduling and real OneDrive sign-in remain unverified. This does not claim the full stable-release gate.
