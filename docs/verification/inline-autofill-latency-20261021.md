# 网页账号选择到密码填入的延迟验证

日期：2026-10-21。用户反馈为网页输入框旁的账号菜单，数据来自 Monica 本地库。

## 结论与实现

真实 Edge 中复现了随库大小增加的延迟。填充前原先复制整个活动库、计算整库凭据显示信息，并两次序列化完整加密库以比较版本。5000 条额外账号的分段探针中，整库复制约 24–38 ms，两次序列化合计约 15–47 ms，而字段上下文检查通常约 2 ms。

`fillLogin` 现在指定所选账号读取上下文，仅复制该账号及 `findBoundTotpItem` 找到的验证码来源。菜单查询继续使用完整上下文，以保留凭据组编号、排序和匹配语义。显式绑定、旧 Android 反向绑定、内联 OTP 回退和成功填写后才消费 HOTP 的行为保持原有路径。

加密库版本改为保留不可变密文字串及复制后的元数据，直接比较 version、cipher、iv、完整 ciphertext、updatedAt 和 KDF。派发前仍重新读取持久库与会话，拒绝期间的加密数据或授权变化；没有改成只比较时间戳，没有增加秘密写入重试。原有页面来源、活动标签页、字段会话及站点/字段禁用检查继续执行。

## 前后实测

使用已安装的 Microsoft Edge、独立测试配置和真实 dist 扩展，路由到合成 HTTPS 登录页面。每组测量 6 次实际账号菜单点击；在页面捕获点击事件，以密码输入框的 `input` 事件计算间隔，避免把 Playwright 等待轮询计入延迟。测试账号均为合成数据，管理页在前后两轮均保持打开。

每条额外账号含独立网站及约 1200 字符备注。下表为额外账号数，另有 3 条基础测试账号。前后对比均未安装分段计时探针。

| 额外账号 | 修改前中位数 | 修改后中位数 | 观察 |
| --- | ---: | ---: | --- |
| 0 | 10.55 ms | 12.15 ms | 小库无明显收益，毫秒级波动 |
| 1000 | 118.75 ms | 37.75 ms | 中位数降低约 68%，修改前尖峰较明显 |
| 5000 | 139.50 ms | 58.15 ms | 中位数降低约 58% |

原始点击到输入耗时（ms，四舍五入至一位小数）：

- 小库，修改前：10.6、10.6、7.8、15.3、10.5、8.8；修改后：10.7、20.1、22.9、12.8、11.5、10.2。
- 1000 条额外账号，修改前：236.4、64.0、43.8、173.5、401.3、46.4；修改后：34.0、27.8、21.2、41.7、103.0、41.5。
- 5000 条额外账号，修改前：114.7、146.3、121.4、137.8、184.2、141.2；修改后：68.8、47.5、90.3、47.3、40.5、78.0。

这是本机合成库和测试页面的样本，未测量用户实际库与发生问题的具体网站，也不代表所有网站的固定响应时间。仍需两次持久库读取及字段检查；本次没有添加跨请求的授权缓存。
