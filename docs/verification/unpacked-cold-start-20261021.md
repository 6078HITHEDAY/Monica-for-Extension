# 解压扩展重启问题排查（2026-10-21）

## 用户反馈与当前结论

用户转述：解压 ZIP 加载的插件在每次电脑重新开机后“掉加载”，到扩展管理页手动重新加载才恢复。尚未确认故障时是扩展被停用、图标消失、页面打不开，还是自动填充不响应；故障机器的浏览器版本和错误记录待补充。

本机安装版 Edge 中未复现，不能据此宣布问题已修复。此次没有针对未证实原因修改启动代码，也没有实际重启用户的电脑。验证覆盖浏览器冷启动和异常退出，不等同于故障机器的系统重启。

## 本机验证

使用 Edge 155.0.4283.62、独立临时 profile、本次生产 `dist` 和合成密码库。确认扩展持久安装记录为 `location: 4`、内部接口显示 `UNPACKED`、状态 `ENABLED`、无 disable reasons 和运行时错误。所有后续启动均不传 `--load-extension`，也不重复加载或重新启用扩展。

| 场景 | 结果 |
| --- | --- |
| 持久解压安装后首次无加载参数冷启动 | 管理页与后台正常 |
| 连续三轮关闭/重新启动浏览器 | 每轮自动恢复扩展，密码库保持锁定；解锁后管理页与 popup 正常，无页面异常 |
| 强制终止独立测试浏览器后重新启动 | 管理页正常，合成密码库仍为 locked |
| CDP 停止后台，再直接打开 popup | worker 从 stopped 自动进入 running，popup 显示可用的解锁界面，状态请求成功 |

额外运行真实 Edge 测试：

```powershell
npx playwright test tests/e2e/runtime-startup.spec.ts tests/e2e/manager-startup.spec.ts
```

两项通过：Windows Hello 状态延迟不阻塞管理页；消息接收器暂不可用时，客户端仅重试不含秘密的运行时探测，恢复后正常执行操作。

本机证据保留在 `%TEMP%/monica-cold-start-20261021/`。测试浏览器已关闭；未改变用户浏览器的安装或配置。

## 测试方式的重要区别

仅由 `--load-extension` 加载时，浏览器记录的安装位置是 `COMMAND_LINE`（location 8）；下一次不带该参数启动，扩展可能不加载，直接访问其地址可出现 `ERR_BLOCKED_BY_CLIENT`。这与通过扩展管理页持久安装的 `UNPACKED`（location 4）不同，不能用前者的失败推断用户问题的原因。

已有一些重启测试在每次启动时都会重新传入加载参数，未单独证明持久解压安装能够跨启动恢复，因此本次额外执行了上述实际持久安装验证。

## 下一步所需证据

故障发生当下、手动重新加载之前，记录浏览器及版本、扩展是否启用、扩展管理页的错误原文和解压目录。若只是后台标为“不活动”，还需确认点击插件是否能够自动唤醒；MV3 后台空闲停止本身不代表扩展被卸载或停用。

在匹配复现或取得故障记录后再选择修复位置，避免把正常锁库、后台休眠、浏览器停用或目录丢失混为同一故障。
