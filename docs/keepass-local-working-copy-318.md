# 本地 KDBX 工作副本与密码项目移除

2026-10-09：扩展 `0.1.37` 当前工作树已实现并完成本批验收。用户选择的原文件不自动覆盖；已保存的修改保留在本机加密 KDBX 工作副本中，最后通过“导出 KDBX”保存文件。锁定或重启后，重新选择原文件或最近导出的文件并提供原密码／密钥文件，即可恢复最新工作副本。

## 实现与边界

- 已初始化的本地 KDBX 支持移除项目内选定密码／凭据组，复用现有确认、撤销、恢复记录和原子文件提交。至少保留一条密码；移除的原条目进入回收站，共享附件转交给保留的条目。
- KDBX 文件继续使用原格式、加密方式和数据库凭据。数据库密码、密钥文件仅存在于解锁会话；独立随机回执密钥保存在 Monica 已加密的密码源配置中，管理页只获得非秘密的原文件 SHA-256 标识。
- 整个加密文件和加密操作回执在同一 IndexedDB 提交中保存，并校验版本。写入前失败、已提交但响应丢失、并发版本变化及重复恢复分别测试。普通项目同步、分组、历史和附件修改复用持久化通道。
- 重新打开文件与项目写入使用相同队列。正在解密时锁库或发起新解锁，旧请求不能重建已清除的会话；来源及 Monica 解锁会话在保存配置时再次核验。
- 若已编辑的工作副本丢失，不会用旧原文件静默重建。选中未知外部修改的文件时保留本机副本并提示先导出、另建密码源。已有来源在管理页不能切换本地／WebDAV 类型，避免覆盖另一来源的恢复记录。
- 导出前先同步待写入修改；剩余队列或冲突会阻止导出不完整文件。只有成功保存导出元数据后才清除“待导出”状态。原文件仍由用户自行保存。
- 提示明确指向“已保存的修改”；失败的保存请求不会被宣称已经持久化。七种翻译目录同步更新。本批没有改动 Android 产品代码、已有 Passkey 密钥／ID 或刻意保留的零计数策略。

Edge 两个文件场景分别使用 KDBX 3 密码＋密钥文件、KDBX 4 密码。均通过实际密码源弹窗导入、立即同步、项目编辑器移除／撤销／确认、关闭浏览器、相同隔离配置重启、重选未修改原文件、导出下载。随后再次通过编辑器保存备注、同步并锁库，依次拒绝外部改动文件和错误密码，再用上一次导出文件恢复最新备注并再次导出。

独立解密导出文件，验证原 KDBX 主版本、剩余／回收站数量、稳定条目标识、受保护密码及凭据字段、精确大整数 `9007199254740993`、共享附件 SHA-256 和未变化的附件保护状态。原文件 SHA-256 始终不变，控制台错误为空。第三个 Edge 测试覆盖 WebDAV、OneDrive、MDBX 待恢复操作的设置入口；它使用模拟界面状态，不属于真实云账号验收。

每个文件场景的 `evidence.json`、原始／两次导出 KDBX、浏览器版本记录和截图均在 `.artifacts/keepass-local-edge-verified/`。最终源码、构建及证据文件散列见 `.artifacts/keepass-local-acceptance-manifest.json`。

最初实际浏览器发现管理页公共配置漏传本地文件标识，导致仍禁用移除；修复后基础两场景通过，原失败保存在 `keepass-local-edge-first/`。扩展普通编辑步骤时测试错误地寻找“备注”，真实字段为“恢复备注与笔记”，原超时保存在 `keepass-local-edge-final/`，修正后完整三场景通过。初始类型命令的 PowerShell 参数引用问题也已修正。默认仓库设置下 `git diff --check` 通过；禁用自动换行转换的一次检查误把 CRLF 识别为尾随空白，没有因此批量重写文件。
