# Wi-Fi retained trash and Android interoperability

Validation date: 2026-10-15. Development `dist` remains version 0.1.39; the published 0.1.39 archive is unchanged.

Retained deleted MDBX objects can now be disclosed explicitly for synchronization. The extension overlay uses the existing active-session Tiga entry authorization, audit transaction and payload bounds. Ordinary object reveal still rejects deleted content. Power policy still rejects disclosure in the conservative browser device context. The source scan reads the retained payload at the same content revision and distinguishes trash from an explicit purge; it never guesses that an unavailable payload is empty.

Receiving a restoration restores the native object before applying its content in the same atomic write. A first-seen purge is persisted as Android-compatible deleted root metadata, without creating an object of a guessed type. Later real content consumes that marker atomically. This preserves native object-type immutability. A first implementation using an empty object exposed the engine's immutable-type check during the real browser test and was replaced before committing.

Inbound retained trash includes its attachment bytes. Explicit replacement/removal lists supersede old local attachments, including while the item is trashed; omitted lists and content-free tombstones preserve the existing retained attachments. The native source keeps original attachment identities and hashes. Legacy title-only folders use Android's Java name-UUID algorithm and do not guess between duplicate root folder names. Unknown top-level object wire fields are stored in the encrypted native payload and projected back without overriding current known fields or rounding JSON numeric lexemes.

Native incoming batches allow up to 128 records instead of a fixed 32. Actual pre-write plan limits can reduce a batch only between complete dependency/password groups. A write failure or uncertain result never retries a different plan. An individually oversized connected group is still rejected before partial adoption. Native group lookup also retains existing project membership when a deletion no longer contains the group data.
