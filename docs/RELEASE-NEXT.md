# Monica for Extension — 下一版 / Next release

> 未发布 / Unreleased。当前开发构建仍为 0.1.37；已发布说明保持原样。

## 中文

- 加强 MDBX 跨库移动的数据保护：删除前重新核对来源附件，并将整个数据库的提交摘要加密保存；即使条目版本没变，后续附件变化也会阻止删除。回复丢失或浏览器重启后继续使用原删除回执，不重复删除、不自动放宽版本检查；兼容旧版已提交回执，待恢复期间同步不会覆盖来源快照。
- 本地项目现可移动到 Bitwarden：自动包含完整密码项目和支持的 SSO 关联，保留可迁移 Passkey、密码历史及附件。目标全部回读校验后，一次性纳入目标并移除本地原件；中断后可恢复，重复执行不重复创建。来源在传输期间被修改或出现新关联时停止移除，保留两端数据；远程来源继续使用复制。复用现有移动确认入口，补齐各语言提示并改善暗色提示文字对比度。
- 旧 Monica Android WebDAV 快照现可将通过完整性校验的密码项目、可迁移 Passkey、密码历史和附件批量复制到 Bitwarden，中断后可恢复；原凭据、零计数及来源备份保持不变。同批成员共用一次整库读取，减少重复下载。校验附件归属、大小和校验和，保留合法空文件；无法完整表示的字段或历史明确阻断，源备份变化时要求重新同步。旧 WebDAV 快照仍不作为网站新建 Passkey 的直接保存目标。
- KeePass 来源现可将通过完整性校验的密码项目、可用 Passkey 和附件批量复制到 Bitwarden，并在浏览器中断后恢复；新客户端可读取附件并使用原 Passkey 登录。只包含旧密码差异的 KDBX 历史可转为 Bitwarden 密码历史；旧快照中的不同字段、附件及无法表示的原生设置会明确阻断。修复旧本地条目缺少冗余库编号、Passkey 派生标记和隐藏字段类型差异导致的误报，同时严格检查字段值、保护状态和完整项目成员。MDBX 预览也会拒绝尚未同步的可选字段清空。
- 批量复制到 Bitwarden 新增 MDBX 来源：可传输通过逐字段校验的密码、整组凭据、可用 Passkey 和附件。直接核对原生库身份、版本、项目成员及文件，避免遗漏未同步的凭据；未知字段或无法保留的关联会明确阻断。修复内部根目录被误报为分类缺失，密码项目成员清单在同轮操作中复用，避免重复扫描。补齐 MDBX Passkey 的可发现性、用户验证偏好、创建／使用记录及图标元数据，保留旧凭据、私钥字节和原计数；未知字段格式原样保留并提示受限。
- 修复浏览器本地 Passkey 复制到 Bitwarden 时因缺少独立公钥字段而被误判为不可转移的问题：保存前验证原公钥与目标私钥匹配，保留凭据 ID、私钥字节和原计数；新客户端导入按 Android 的策略要求用户验证。补齐默认密码类型及文本／隐藏字段的等价转换，保留应用信息、地址、重复自定义字段、网址规则和密码历史；无法保留的字段、备份属性及关联仍在预览中明确阻断。
- 批量传输现已接入 Bitwarden 个人密码库目标、原生文件夹及恢复入口。复制完整 Bitwarden 记录时自动包含密码、验证码、全部 Passkey 与关联账户，重建 SSO 和密码项目身份，并核验历史、字段及附件；整批核验完成后一次性入库。文件夹或项目创建回复丢失后先查找已保存结果，无法唯一确认时停止再次创建。仅可取消尚未尝试写入的操作，来源始终保留；旧 Passkey 的凭据、私钥字节和计数不变。本地项目需通过逐字段无损检查，受限项目及整个关联组会在预览中说明原因；跨库移动和其他来源的原生数据转换仍待补齐。
- Bitwarden 上传 Passkey 现与 Android 一致：注册时不允许备份的凭据会明确提示并保留来源，避免丢失不可改变的注册标志；零计数和已有私钥不变，无效计数不再被静默修正。修复 UUID／Base64URL 表示导致上传中断后无法识别已保存凭据的问题；兼容旧恢复记录，重复匹配时保留冲突且不再上传，消除误报“远端已删除”。损坏或未知版本的同步回执会停止读取并保留加密原库，避免丢弃恢复信息后重复写入。
- 批量传输现可选择 KeePass 本地文件、WebDAV 或 OneDrive 数据库及原生文件夹，复制完整密码项目、可用 Passkey 与附件；同库移动保留原项目身份。文件保存后即使浏览器中断，也可从目标下方恢复，保留后续编辑及删除；只有尚未写入文件的操作可以取消。本地文件完成后需导出并保存 KDBX，云端在带版本检查的上传完成后确认成功；不覆盖另一端的冲突修改。
- 修复真实 KDBX 条目使用 Base64 身份、字段引用使用十六进制身份时无法匹配的问题，用户名与密码引用可正确解析。整组传输保留原生字段、历史及附件，复制时重建项目及内部引用；原 Passkey 凭据、私钥字节与零计数不变。修复 Base64URL 私钥被误报为无法完整保存、旧格式 KDBX 已保存的移动被误报为未保存的问题。锁定会中止待发上传，目标变化会停止恢复，完成迁移不会覆盖刚刷新的 OneDrive 登录令牌。
- 修复 KeePass 操作回执超过保留数量后，旧请求可能被重复执行的问题。过期回执保留不含密码内容的操作标记，重试会提示检查当前内容，不会重新创建已删除分组或覆盖后续修改；浏览器重启后仍有效。现有工作副本与回执原位升级，新操作继续可用。
- 批量传输可选择 Monica 本地库作为目标；本地库卡片也提供入口，可复制整组密码及附件，或在本地文件夹间移动。项目、附件与恢复回执一起加密提交，预览后内容变化会停止保存；浏览器重启后的重试不会覆盖后续修改或复活已删除的附件。新增本地附件上传、下载、替换与删除，替换和删除会检查当前版本，防止旧窗口覆盖新内容。单次传输与每个项目的附件总量上限为 16 MiB。
- 修复加密密码库写入容量与读取上限不一致的问题：超过 64 MiB 时在覆盖原库之前停止保存，避免下次无法解锁；传输摘要及附件读取的临时明文字节会及时清理。
- Bitwarden 项目复制到 MDBX 时可携带 Steam maFile 等附件，Passkey／验证码投影会读取其所属远端记录的附件；校验加密完整性和真实文件大小，复制后回读目标并核对 SHA-256，中断后可重试且不重复复制。个人附件按项目读取，避免每个文件都下载整库。修正附件传输失败时的临时明文清理；尚未具备持久删除恢复的 KeePass、Bitwarden 和旧 WebDAV 来源暂仅允许复制，移动在预览阶段说明原因并保留来源。
- Passkey 和 Steam 页面新增批量传输入口，可直接复制或移动到 MDBX；候选项目沿用当前搜索、数据库和文件夹范围，包含分页之外的匹配结果。修复多个 MDBX 来源使用相同文件夹 ID 时路径混淆的问题；目录不可读的来源单独列出原因，保留分类时不再静默丢弃缺失的父目录。共享 Bitwarden 远端记录的项目暂不允许单独跨库移动，复制仍保留来源。
- 去掉设置页语言和显示模式下拉框的内层聚焦包边；鼠标悬停及展开菜单只轻微提亮整行，键盘定位保留单层整行提示，并适配系统高对比度。
- 整理设置页：语言、显示模式、自动同步和表单旁自动填充可在首页直接操作；按通用、同步与填充、密码库与安全分组，二级入口由十个缩减为四个。合并 Windows Hello 与保护方式、备份与迁移，移除重复的显示模式及独立安全说明入口。收紧分组间距与留白，语言/显示模式行由约 108px 缩至 72px，保留大字号下的完整文本和操作空间；补齐编辑内容页遗漏的多语言词条。
- 加固设备密钥隔离：将旧存储中的设备密钥迁移至扩展专属 IndexedDB，网页内容脚本不能读取；迁移成功提交后才清理旧副本，保留原密钥与密码库数据，重试不会用旧副本覆盖已迁移密钥。迁移后的设备密钥模式不能直接降级到旧构建，建议保留密码保护的备份。
- 修复诊断脱敏遗漏带引号的密码、多词口令及提供方 token／密钥字段的问题；无效的已解密 JSON 不再把原文片段带入错误消息。缩短密码库明文字节缓冲区的存活时间。
- 更新有已知漏洞的测试依赖；本次完整 npm 依赖审计无已知漏洞告警。审查范围与剩余限制见安全审查报告；设备密钥模式仍依赖浏览器及操作系统保护，推荐使用强主密码。
- 修复 Android／Bitwarden 的标准加密 maFile 附件在插件显示“不可用”：兼容标准附件及旧 Monica 格式，新上传使用 Bitwarden 标准格式，已准备的旧上传可继续恢复。附件读取失败后，即使服务器版本号未变也会重试；成功后复用缓存。完整保留数字 SteamID，修复普通网页 URL 干扰密钥读取、缺少附件大小时跳过加载的问题。Steam Guard 验证码不依赖会话 token。
- 修复 Steam 登录项丢失验证码编码信息、`encoder=steam` 条目未显示的问题；读取 Android 标记的 KDBX maFile 附件，无法读取密钥的已识别条目继续显示为不可用。
- 密码库筛选使用原生文件夹身份，支持 Steam、Passkey 等页面按数据库和文件夹筛选。不同数据库的同名文件夹保持独立，KeePass 路径正确显示，根目录可单独筛选。各页面选择保存在加密密码库中，重新打开后恢复。
- Passkey 兼容标记在列表与详情往返时立即复用；会话缓存有容量和有效期限制，密钥变化或锁定后重新检查，减少重复计算和标记闪烁。
- 无待写入修改的本地 MDBX 不再周期性触发同步任务；编辑后的本地写回与云端同步继续保留。
- 修复 MDBX 批量传输把 Passkey“复制”执行为“移动”的问题：副本保留原凭据 ID、私钥及计数，来源记录不变。目标数据库已有相同凭据时提前阻止；受限条目可取消或跳过，复制中断后可重试。

以上是已实现的改动，完整 Android 对齐仍在进行。传输目前提供本地库、MDBX、KeePass 和 Bitwarden 个人库目标；跨后端原生字段矩阵及外部来源的持久删除恢复尚未补齐，同 Wi-Fi 设备同步仍待接入，不据此宣称所有数据库之间已完成互通。尚未发布新安装包或更新商店。

## English

- Hardened cross-vault MDBX moves: source attachments are rechecked before an encrypted deletion intent records the complete vault revision. Later attachment changes block deletion even when item heads are unchanged. Lost replies and restarts reuse the original receipt without duplicate deletion or relaxed revision checks; committed legacy receipts remain recoverable, and pending moves protect their source snapshots from sync.
- Local items can now be moved into Bitwarden, including complete password projects, supported SSO dependencies, portable Passkeys, password history and attachments. After full destination readback verification, one encrypted transaction adopts the destination and removes local originals. Interrupted transfers resume without duplicate creates. Source edits or new dependencies stop removal and preserve both sides; remote sources continue to use Copy. The existing move confirmation is reused, with complete locale instructions and more readable warning text in dark mode.
- Eligible password projects, portable Passkeys, password history and attachments from legacy Monica Android WebDAV snapshots can now be batch-copied into Bitwarden with interruption recovery. Original credentials, zero counters and source backups remain intact. Each batch shares one archive read, avoiding repeated whole-vault downloads. Attachment ownership, size and hashes are verified, including valid empty files; unsupported fields/history or changed source snapshots stop the affected transfer. Legacy WebDAV snapshots remain unavailable as direct website Passkey registration destinations.
- KeePass sources can now copy eligible password projects, usable Passkeys and attachments into Bitwarden with interruption recovery. A fresh client can read copied files and authenticate with the original credential. KDBX snapshots containing only old-password differences can become native Bitwarden password history; distinct historical fields/files and unrepresentable native settings are explicitly blocked. Fixed false change reports from missing redundant database IDs, derived Passkey labels and equivalent hidden-field types while retaining checks for values, protection and complete project membership. MDBX previews also reject unsynchronized removal of optional fields.
- Batch copies into Bitwarden now support MDBX sources for passwords, complete credential groups, usable Passkeys and attachments that pass explicit field-preservation checks. Native vault identity, revisions, project membership and files are verified to detect unsynchronized siblings; unknown fields and unsupported relationships are explicitly blocked. Fixed false missing-folder warnings for the internal root, and reuse project catalogs within each operation to avoid repeated vault scans. MDBX Passkeys now preserve discoverability, user-verification preferences, creation/usage metadata and icons without changing existing credential IDs, private-key bytes or counters; unfamiliar metadata shapes remain intact and are marked restricted.
- Fixed local browser Passkeys being incorrectly blocked when copied to Bitwarden because its native format omits a separate public key. Before saving, Monica verifies that the original public key matches the destination private key, preserving credential IDs, private-key bytes and counters. Fresh imports require user verification, matching Android's policy. Default password types and text/hidden fields now convert equivalently while retaining application details, addresses, duplicate custom fields, URL rules and password history. Unrepresentable fields, backup properties and relationships remain explicitly blocked in the preview.
- Batch transfer now offers personal Bitwarden destinations, native folders and recovery controls. Full native Cipher copies include passwords, OTPs, every Passkey sibling and linked accounts, rebind SSO and project identities, and verify fields, history and attachments before atomic batch adoption. Lost folder or Cipher replies are reconciled against saved results; ambiguous or unknown outcomes stop another application create. Only operations with no attempted writes can be cancelled. Sources, Passkey credential/private-key bytes and original counters are retained. Local entries must pass explicit field-preservation checks; unsupported entries block their whole connected group with an explanation in preview. Cross-vault moves and native conversion from other backends remain unfinished.
- Bitwarden Passkey uploads now follow Android's restriction on credentials registered without backup eligibility: the source is retained with an explicit explanation instead of losing an immutable registration flag. Existing keys and zero counters are preserved; invalid counters are rejected rather than silently changed. Interrupted uploads now recognize equivalent UUID/Base64URL representations and retain compatibility with old recovery receipts. Ambiguous matches remain conflicts without another upload or a misleading remote-deletion warning. Invalid or unknown-version receipts stop vault loading while retaining the encrypted original, preventing recovery information from being discarded and a write from being repeated.
- Batch transfer now supports KeePass local files, WebDAV and OneDrive destinations with native folder selection. Copy complete password projects, usable Passkeys and attachments, or move native entries within the same database while retaining their identities. Resume committed files after browser interruption without overwriting later edits or deletions; only unwritten operations can be cancelled. Local files still require exporting and saving the KDBX. Cloud transfers complete after version-checked publication and stop on conflicting peer changes.
- Fixed native KDBX field references failing to match base64 entry identities against hexadecimal reference UUIDs. Batch transfers preserve native fields, history and attachments, rebasing copied project/reference identities while retaining Passkey credential IDs, private-key bytes and zero counters. Fixed false preservation failures for Base64URL private keys and false unsaved-change warnings after moves in older KDBX formats. Locking aborts pending uploads, changed destinations stop recovery, and transfer completion retains freshly rotated OneDrive tokens.
- Fixed old KeePass requests becoming executable again after their detailed receipts exceed the retention limit. Expired receipts now retain compact operation markers without password contents; retries ask users to check current data instead of recreating deleted groups or overwriting later changes, including after browser restart. Existing working copies and receipts migrate in place, and new operations remain available.
- Batch transfer now offers the Monica local vault as a destination, with an entry on the local-vault card. Copy related password items and attachments together, or move them between local folders. Items, files and recovery receipts commit in one encrypted transaction; changed previews stop before saving, and retries after browser restart preserve later edits and deletions. Local attachments support upload, download, replacement and deletion, with revision checks to prevent stale windows overwriting newer contents. Attachments are limited to 16 MiB per transfer and per item.
- Matched encrypted-vault writes to the reader's 64 MiB limit: oversized writes now stop before replacing the readable vault. Temporary plaintext used for transfer fingerprints and attachment reads is cleared.
- Bitwarden-to-MDBX copies now include Steam maFiles and other attachments, including parent-Cipher files for Passkey and OTP projections. Authenticated downloads establish actual file sizes; destination readback verifies SHA-256, and interrupted copies can be retried without duplication. Personal attachments fetch the relevant Cipher instead of downloading the entire vault for each file. Temporary plaintext is cleared on transfer failures. KeePass, Bitwarden and legacy WebDAV sources currently allow copying only; moves remain blocked in the preview until durable source-deletion recovery is integrated.
- Added a batch-transfer entry on Passkey and Steam pages for copying or moving to MDBX. Candidates retain the current search, database and folder scope, including matches beyond the current page. Fixed mixed folder paths when multiple MDBX sources use the same collection ID. Unreadable source folders are reported individually; preserving categories no longer silently drops missing ancestors. Items sharing a Bitwarden remote record cannot be moved individually across databases yet; copies retain the source.
- Removed the nested focus outline from language and display-mode settings. Hovering or opening a menu subtly highlights the row; keyboard navigation keeps a single row-level indicator, including system high-contrast mode.
- Reorganized settings into General, Sync and autofill, and Vault and security. Language, display mode and the sync/autofill switches work directly on the home page; secondary destinations are reduced from ten to four. Combined Windows Hello with protection settings, and backups with migration. Removed duplicate display-mode controls and the separate security explanation page. Reduced spacing and empty field hints, bringing standard language/display rows from about 108px to 72px while preserving enlarged-text usability. Completed missing editor translations.
- Isolated device keys in extension-origin IndexedDB, inaccessible to content scripts. Legacy keys migrate unchanged; old copies are removed only after commit, and retries never replace an already migrated key with a legacy copy. Direct downgrade of a migrated device-key profile to an older build is unsupported; retain a password-protected backup.
- Fixed diagnostic redaction of quoted passwords, multiword passphrases and provider token/key fields. Invalid decrypted JSON no longer includes source fragments in errors. Reduced the lifetime of plaintext vault byte buffers.
- Updated vulnerable test dependencies; the full npm audit reports no known advisories at review time. See the security review for scope and remaining limitations. Device-key mode still relies on browser and OS protection; a strong master password is recommended.
- Fixed Android/Bitwarden standard encrypted maFile attachments appearing unavailable. The reader supports both standard Bitwarden and historical Monica attachments; new uploads use the standard format and prepared historical uploads remain recoverable. Failed attachment reads retry even when the server revision is unchanged, while successful reads stay cached. Numeric SteamIDs retain their full precision, unrelated website URLs no longer override the secret, and missing attachment sizes no longer prevent bounded reads. Steam Guard codes do not require session tokens.
- Fixed Steam login projections losing secret encoding and omitting `encoder=steam` entries. Android-marked KDBX maFile attachments are read, while recognized entries with unavailable keys remain visible with an unavailable state.
- Vault filtering uses native folder identities across Steam, Passkey and other pages. Identically named folders in separate databases remain distinct; KeePass paths are decoded for display and root entries can be filtered separately. Each page's selection is saved inside the encrypted vault and restored on reopening.
- Passkey compatibility labels reuse completed checks immediately on list/detail navigation. A bounded session cache expires results and rechecks changed keys or a new unlock session, reducing repeated work and flicker.
- Clean local MDBX databases no longer schedule periodic synchronization. Pending local writes and cloud synchronization remain supported.
- Fixed MDBX batch transfer treating a Passkey copy as a move. Copies retain the credential ID, private key and counter while preserving the source. Existing credentials in the destination are blocked before transfer; unavailable entries can be cancelled or skipped, and interrupted copies can be retried.

Full Android parity remains in progress. Transfers now offer local-vault, MDBX, KeePass and personal Bitwarden destinations; the cross-backend native-field matrix, durable foreign-source deletion and nearby-device synchronization remain unfinished. This update does not claim interoperability between every database. No new release package or store update has been published.
