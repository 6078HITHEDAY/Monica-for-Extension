# Bitwarden 项目移除与 Passkey 引用迁移（2026-10-09）

本批把此前的原生 Passkey 保留准备接入完整项目移除协调器，并完成最终本地引用迁移。真实 Edge IndexedDB 的两次浏览器重启恢复通过。**后台来源队列、MV3 管理界面、真实服务和 Android 往返仍未验收，完整互通目标继续进行。**

扩展仍为 0.1.37，HEAD `18dd08d79a5ac454cac5512f85e0dbf55141e395`，修改未提交。没有发布、推送、标签、Android 产品修改或 APK 交付。

## 行为

1. 项目内保留项的同步及附件准备完成后，协调器检查源密码下的 Passkey，生成并持久保存独立原生副本。附件凭据与复制日志一同保存；复制中断重启后使用已有记录，不再执行普通同步或重复上传。
2. 每次删除前及最终回读都会独立读取副本详情、核对加密标记、来源身份、密钥、计数及原生内容。没有完成保留或副本发生变化时，不继续删除。
3. 成功收尾在一次加密保存中迁移原 Passkey 的来源引用，保留原本地记录 ID、凭据 ID、私钥、零/正计数、本地使用统计以及其他来源引用。每个副本的无密码父记录和原生密文同时保存；仅清理本次项目删除队列。
4. 原 Cipher 中的旧 Passkey 投影保留为单独本地 ID 的回收站记录，只带旧 Bitwarden 来源。这样普通同步仍能识别旧来源，而不会把已迁移、仍可使用的 Passkey 当成删除项。两个连续普通同步周期已验证无冲突、无重复活跃凭据、原本地 ID 不变。
5. 复制期间普通同步在发出网络请求前停止；密码库保存层也拒绝通用投影替换。完整协调器仍可以继续复制、验证与最终采用。
6. 副本发生明确内容变化会触发源密码补偿恢复。远端已 committed、但本地尚未采用时，恢复会重新核对；如果另一端恢复了源密码，或修改了副本，转入补偿与最新内容回读，不重新删除源密码。缺失、不可读或网络不确定仍保留恢复记录，不冒充成功。

恢复/取消时不删除已创建的独立副本，也不覆盖另一端写入的最新内容。副本的后续归并、取消时的管理展示与不确定结果的明确处理仍属于后续恢复界面范围。
