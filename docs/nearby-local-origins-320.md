# Nearby local source archives

The local-copy transaction already retains original provider envelopes in encrypted `localItemOrigins`. Nearby capture previously blocked such items unless a nearby receipt existed; that receipt path could send the visible projection while omitting its source archive. Two failing regressions reproduced both paths.

## Preservation and security

- Capture and adopt the archive through an Android-compatible label, `monica:extension-local-origins:v1`. Preserve every original descriptor string and opaque payload string, including whitespace, numeric tokens, binary encodings, provider IDs and revisions. Unknown source **formats** remain opaque. Unsupported descriptor/envelope schema changes are rejected, never flattened.
- Archive data is retained only in encrypted local storage and wire receipts. It does not enter `sourceRecords`, create provider accounts or remote bindings, become a visible attachment, or become input to credential discovery. Old credentials inside a complete source envelope remain archival data; active Passkey eligibility and signing policies remain separate and unchanged.
- Union immutable archived versions using the complete descriptor and payload. A reused provider content hash/revision cannot collapse different bytes. De-duplicate identical records and sort their descriptors for stable reciprocal synchronization; payload strings remain exact. Missing labels from an older peer cannot erase previously retained archives.
- Include archives in native binding guards, independently of the full source snapshot. Even an archive-only edit with an unchanged provider hash/revision invalidates the old binding guard. Build a per-item index once per snapshot/transaction instead of rescanning all archives for each item.
- Reconstruct archives retained only in old encrypted receipts. This was verified with an additional failing regression: deleting the separate archive projection to emulate an older client, then receiving a later edit without the label, must still retain and acknowledge the archive.
- Store adopted items, archive union, attachments and acknowledgements atomically. Receipt replay recovers a lost successful-write response without overwriting later edits. Empty tombstones retain archival recovery data. Portable backups and later local-copy transactions retain the same records.
- Apply bounded structural validation before mutation: up to 1,024 archive records per item, 20,000 local archive owners, and the existing 1 MiB UTF-8 nearby record limit including the visible projection and labels. Oversized or malformed archives fail explicitly without partial writes. Original provider hashes are preserved as metadata; authenticated transport/encrypted storage and complete-content guards protect this transfer.

The standard source descriptor remains eight possible string fields: providerId, itemId, remoteId, revision, format, encoding, payload and contentHash. The protocol does not interpret JSON/XML/provider formats inside payload. Binary encodings are retained literally rather than decoded into executable or live provider state.

## Validation

- Eighteen dedicated origin tests cover receipt-free and receipt-bearing capture, encrypted persistence/restart/edit/backup, lost commit replies, archive-only stale guards, immutable union, absent labels, receipt-only legacy recovery, empty tombstones, exact binary/opaque payloads and malformed/version/descriptor/UTF-8 size failures.
- Three cases run the actual `prepareLocalTransferBatch` / `applyLocalTransferBatch` transaction with synthetic Bitwarden, KeePass and MDBX readback resources, then nearby adoption and another local copy. This verifies archival ownership and copy behavior, not fresh remote-backend IO.
- The affected suite passed 258 tests in 12 files before the final receipt-only regression; that extra regression first failed and then the final three affected files passed all 44 tests. This is 259 distinct passing cases in the block, not a new full-repository run. Project/interop TypeScript, strict changed-E2E types, normal production build, pinned browser engine provenance and package security audit passed.
- Installed Edge 155.0.4283.45 used two isolated profiles, real Native Messaging/Noise and the production dist background. Source archives labelled as Bitwarden/KeePass/future formats included exact large-number/decimal JSON and an approximately 85 KB opaque string. All three original archives arrived and survived both-browser/native restart and reciprocal edits. No provider bindings were introduced.
- The same real transfer retained nested/empty folders, root tags, a 600,000-byte attachment, original Passkey key/credential bytes and a signature verified with its original public key. Source counters remain 0/19; the separate positive-count credential is excluded from active export. Archived source envelopes are not claimed to have had their embedded historical credentials independently activated or tested.

Evidence stays local under `.artifacts/nearby-origins-*`, including the two initial failing unit regressions, the receipt-only failure/repair, unit/build/type/security logs and production-browser `evidence.json`. The first attempted build hit the existing broad icon-inventory scanner on a schema-property string; the ensuing browser run used the previous dist and reproduced the missing archive. After avoiding that false-positive while retaining strict envelope validation, the production build and real-browser scenario passed. The final build passed the full scenario in 15.5 seconds at `.artifacts/nearby-origins-edge-legacy-final/`. Native registration is restored after each run. The actual build hash is recorded in the browser evidence.

Android source was read, not modified: main `c791b28f3a39b814c5dde28f51f2eeb3349322e1`, development 1.0.320. `DeviceRoomVaultMetadata.save/supplement` encrypt and preserve labels.
